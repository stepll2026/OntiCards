-- 辅助函数说明：
-- 
-- 1. 字符串类型判断：
--    - varchar, char, text 等类型需要统计空字符串
--    - 其他类型（数值、日期等）只统计 NULL 值
--
-- 2. NULL 值统计：
--    SUM(CASE WHEN "column_name" IS NULL THEN 1 ELSE 0 END)
--
-- 3. 空字符串统计（仅字符串类型）：
--    SUM(CASE WHEN "column_name" IS NOT NULL AND TRIM("column_name") = '' THEN 1 ELSE 0 END)
--
-- 4. 缺失率计算：
--    ROUND(CAST(100.0 * (null_count + empty_str_count) AS DOUBLE) / total_rows, 2)

--@@split

-- 防错与稳健性建议（生成 SQL 时务必遵守）：
-- 1. 日期/时间列：
--    - 若列类型为 timestamp/date，直接使用 CAST(col AS DATE)；不要对 varchar 直接 DATE(col)。
--    - 若列是字符串存储时间，使用 TRY_CAST(col AS DATE) 或 TRY_CAST(DATE_PARSE(col, '%Y-%m-%d %H:%i:%s') AS DATE)，避免 INVALID_CAST。
--    - 进行日期比较时，优先使用 CAST/TRY_CAST，并在 WHERE 中先判空再比较。
--      例如：
--        WHERE col IS NOT NULL
--          AND TRY_CAST(col AS DATE) = CURRENT_DATE
--    - 避免 DATE(col) 直接作用于字符串，以免触发 “INVALID_CAST_ARGUMENT”。
-- 2. 数值列：
--    - 若存为字符串，使用 TRY_CAST(col AS DOUBLE/INTEGER)；禁止直接 CAST，避免非数值报错。
-- 3. 字符串列统计空值：
--    - 空字符串判断使用 TRIM(col) = ''，并先判 NOT NULL。
-- 4. 任何 CAST 建议替换为 TRY_CAST，确保遇到脏数据时返回 NULL 而不是报错。
-- 5. 组装动态 SQL 时，注意对标识符使用双引号，对字面量使用单引号。

--@@split

-- Catalog / Schema / 表名 防错约束（务必遵守）：
-- 1) 只允许使用“白名单”中提供的 catalog.schema.table；不要臆造 catalog 名（如 oracle、mysql 等）。
-- 2) 生成 SQL 前先从输入表清单提取合法的 catalog 与 schema，拼接时必须复用这些值。
-- 3) 执行前可扫描 SQL 中出现的 catalog.schema：
--      - 若发现不在白名单的 catalog，直接拒绝执行并要求重试。
--      - 若缺少 catalog 或 schema，拒绝执行，避免落到默认 catalog。
-- 4) 所有标识符一律双引号包裹："catalog"."schema"."table"；不要省略 catalog。
-- 5) 多表/多列场景下，每张表都必须是白名单内表；若模型生成了白名单外的表，直接报错并重试。

--@@split
