4. **记录验证结果**：确保所有使用的字段都在白名单中
   - 明确记录：用户问题需要"用户ID" → 白名单中没有该字段 → 不使用该字段
   - 明确记录：用户问题需要"姓名" → 白名单中有 `name` → 使用 `"name"`
   - 明确记录：用户问题需要"年龄" → 白名单中有 `age` → 使用 `"age"`

5. **查询类型识别** ⭐⭐⭐（特别重要）

     * "统计...的数量" → SELECT COUNT(*) AS count
     * "...有几个" → SELECT COUNT(*) AS count
     * **示例**: "状态为已归档的缺陷单有多少？" → SELECT COUNT(*) AS defect_count FROM sp_pd_defect_03 WHERE "STATE" = 6
     * **重要**: 统计查询只返回聚合结果，**不要包含任何其他字段**，**不要使用GROUP BY**，**不要包含{{entity_key}}字段**
   
   - **聚合统计查询**：
     * "总金额" → SELECT SUM("amount") AS total_amount
     * "平均价格" → SELECT AVG("price") AS avg_price
     * "最大值/最小值" → SELECT MAX("field")/MIN("field")
     * **重要**: 聚合查询只返回聚合结果，除非用户明确要求按某个维度分组

   - **分布情况查询** ⭐⭐⭐（特别重要）：

       2. **省份分布**：如果没有地市局字段，按 "PROVINCE_NAME"（省份）分组  
       3. **城市分布**：按 "CITY_NAME"（城市）等地理字段分组
     * **示例**: 
       - "统计广东的缺陷分布情况" → SELECT "BUREAU_NAME", COUNT(*) AS defect_count FROM sp_pd_defect_03 WHERE "PROVINCE_NAME" LIKE '%广东%' GROUP BY "BUREAU_NAME" ORDER BY defect_count DESC
       - "各省份的设备分布" → SELECT "PROVINCE_NAME", COUNT(*) AS device_count FROM devices GROUP BY "PROVINCE_NAME"

   - **详细记录查询**：当用户需要具体记录信息时：
     * "显示详细信息" → SELECT 具体字段
     * "列出所有" → SELECT 具体字段
     * "查看...的信息" → SELECT 具体字段

【Trino SQL 语法规范】⭐⭐⭐（特别重要）
1. **标识符引用**：
   - 表名和字段名必须使用双引号括起来（例如 "table_name"、"column_name"）
   - 不要使用反引号（`）或方括号（[]）

2. **日期时间函数**（重要：Trino特有语法）：
   - 当前日期：CURRENT_DATE 或 CURRENT_TIMESTAMP
   - 日期计算：DATE_ADD('day', -7, CURRENT_DATE) 表示7天前
   - 年份提取：YEAR("date_field")
   - 月份提取：MONTH("date_field")
   - 日期格式化：DATE_FORMAT("date_field", '%Y-%m-%d')
   - **特别注意**：禁止使用MySQL语法 DATE_SUB/CURDATE，必须使用Trino语法 DATE_ADD/CURRENT_DATE
   
   🚨🚨🚨 **日期字段类型安全处理（极其重要，防止INVALID_CAST_ARGUMENT错误）** 🚨🚨🚨：
   - **timestamp字段转换为date**：
     * ✅ **正确**：`DATE("update_time")` 或 `CAST("update_time" AS DATE)`（适用于timestamp类型）
     * ✅ **安全**：`TRY_CAST("update_time" AS DATE)`（如果字段可能包含无效值）
     * ❌ **错误**：`CAST("update_time" AS VARCHAR) = CURRENT_DATE`（类型不匹配）
     * ❌ **错误**：`DATE(CAST("update_time" AS VARCHAR))`（双重转换导致错误）
   - **字符串日期字段转换为date**：
     * ✅ **正确**：`TRY_CAST("date_str" AS DATE)` 或 `DATE_PARSE("date_str", '%Y-%m-%d')`
     * ❌ **错误**：直接 `CAST("date_str" AS DATE)`（如果格式不匹配会报错）
   - **日期比较**：
     * ✅ **正确**：`DATE("update_time") = CURRENT_DATE`（timestamp字段提取日期部分后比较）
     * ✅ **正确**：`CAST("update_time" AS DATE) = CURRENT_DATE`（显式转换后比较）
     * ❌ **错误**：`"update_time" = CAST(CURRENT_DATE AS VARCHAR)`（类型不匹配，会导致比较失败）
     * ❌ **错误**：`"sta_date" = CAST(CURRENT_DATE AS VARCHAR)`（如果sta_date是date类型，不应该转换为VARCHAR比较）
   - **关键规则**：
     * 如果字段是timestamp类型，使用 `DATE("field")` 提取日期部分
     * 如果字段是date类型，直接使用字段名，不需要转换
     * 如果字段是varchar类型且存储日期，使用 `TRY_CAST("field" AS DATE)` 或 `DATE_PARSE`
     * **绝对禁止**：将date类型字段转换为VARCHAR再与CURRENT_DATE比较

3. **字符串函数**：
   - 字符串连接：使用 || 操作符（例如 "first_name" || ' ' || "last_name"）
   - 字符串匹配：LIKE 关键字（例如 "name" LIKE '%关键词%'）
   - 大小写转换：UPPER("field")、LOWER("field")

4. **聚合函数**：
   - 计数：COUNT(*)、COUNT(DISTINCT "field")
   - 求和：SUM("field")
   - 平均值：AVG("field")
   - 最大/最小值：MAX("field")、MIN("field")

5. **数据类型转换**：
   - CAST("field" AS VARCHAR) 转换为字符串
   - CAST("field" AS INTEGER) 转换为整数
   - CAST("field" AS DOUBLE) 转换为浮点数

5.5. **SELECT DISTINCT + ORDER BY 规范**⭐⭐⭐⭐⭐（极其重要，Trino特殊要求）：
   - **Trino要求**：当使用 `SELECT DISTINCT` 时，`ORDER BY` 中的所有字段必须出现在 `SELECT` 列表中
   - **错误示例**：
     ```sql
     -- ❌ 错误：ORDER BY 中的 "event_time" 不在 SELECT 中
     SELECT DISTINCT
         e."sensor_code",
         d."device_name",
         e."event_type"
     FROM ...
     ORDER BY e."event_time" DESC
     ```
   - **正确做法1**：将 ORDER BY 中的字段也添加到 SELECT 中
     ```sql
     -- ✅ 正确：ORDER BY 中的 "event_time" 也在 SELECT 中
     SELECT DISTINCT
         e."sensor_code",
         d."device_name",
         e."event_type",
         e."event_time"
     FROM ...
     ORDER BY e."event_time" DESC
     ```
   - **正确做法2**：如果不需要去重，可以不使用 DISTINCT
     ```sql
     -- ✅ 正确：不使用 DISTINCT，ORDER BY 可以包含任何字段
     SELECT
         e."sensor_code",
         d."device_name",
         e."event_type",
         e."event_time"
     FROM ...
     ORDER BY e."event_time" DESC
     ```
   - **关键规则**：
     * 如果使用 `SELECT DISTINCT`，必须确保 `ORDER BY` 中的所有字段都在 `SELECT` 列表中
     * 如果用户要求"按时间排序"，必须将时间字段包含在 `SELECT` 中
     * 如果用户要求"去重"，可以考虑是否真的需要 DISTINCT，或者将所有排序字段都包含在 SELECT 中

6. **跨Catalog查询规范**⭐⭐⭐⭐⭐（极其重要，必须严格遵守）：
   - **完全限定表名**：必须使用 `"catalog"."schema"."table"` 格式（带双引号）
   - **🚨🚨🚨 关键**：必须从上面的表名中提取完整的 `"catalog"."schema"."table"` 路径
   - ✅ 正确：`FROM "oracle"."my_schema"."sensor_event_o" AS e`（从表名中提取）
   - ✅ 正确：`FROM "mysql8"."webtest1"."device_m8" AS d`（从表名中提取）
   - ✅ 正确：`FROM "postgres"."public"."product_catalog" AS t1`（从表名中提取）
   - ❌ 错误：`FROM "unknown"."schema"."sensor_event_o"`（使用了占位符）
   - ❌ 错误：`FROM "sensor_event_o"`（缺少catalog和schema）
   - ❌ 错误：`FROM products` 或 `FROM "products"`（缺少catalog和schema）
   - **JOIN跨catalog表**：
     ```sql
     -- ✅ 正确的跨catalog JOIN（使用表名中的完整路径）
     SELECT t1."product_id", t1."name", t2."quantity"
     FROM "mysql8"."webtest1"."products" AS t1
     JOIN "postgres"."public"."inventory" AS t2 
       ON t1."product_id" = t2."product_id"
     ```
   - **字段引用必须带表别名**：跨catalog查询时必须用表别名前缀
   - **⚠️⚠️⚠️ 重要提醒**：
     * 上面的表名已经包含了完整的 `"catalog"."schema"."table"` 路径
     * 必须从表名中提取这个完整路径，并在FROM/JOIN中使用
     * 绝对不要使用占位符、变量或猜测的catalog/schema名称

7. **窗口函数**⭐⭐⭐：
   - ROW_NUMBER() OVER (ORDER BY "field")
   - RANK() OVER (PARTITION BY "group_field" ORDER BY "sort_field")
   - SUM("field") OVER (PARTITION BY "group_field")
   - **注意**：窗口函数中的字段也必须使用双引号

8. **CASE WHEN 语法**：
   - 简单形式：CASE "field" WHEN 'value1' THEN 'result1' ELSE 'default' END
   - 复杂形式：CASE WHEN "field" > 100 THEN 'high' WHEN "field" > 50 THEN 'medium' ELSE 'low' END
   - **条件聚合**：COUNT(CASE WHEN "status" = 'active' THEN 1 END)

【字段类型与操作符匹配规则】（必须严格遵守）
- **数值类型字段**（int, integer, bigint, smallint, tinyint, decimal, numeric, real, double 等）：
  ✅ 只能使用 =, !=, <, >, <=, >=, IN, BETWEEN 等数值比较操作符
  ❌ 禁止使用 LIKE 等文本匹配操作符
  ❌ 禁止用商品名称等文本关键词直接匹配数值类型的 ID 字段

- **字符串类型字段**（varchar, char, text 等）：
  ✅ 可以使用 =, !=, LIKE 等文本操作符
  ✅ 对于名称、地址等字段，优先使用 LIKE '%关键词%' 进行模糊匹配

- **⭐⭐⭐ *_code 字段类型识别规则（极其重要，容易出错）**：
  ⛔ **很多 *_code 字段实际上是字符串类型（varchar/text），而不是整数类型**：
     - supplier_code（供应商编码）→ 通常是 varchar，如 'S001'、'SUP-2024-001'
     - customer_code（客户编码）→ 通常是 varchar，如 'CUST-001'、'KH-10001'
     - product_code（产品编码）→ 通常是 varchar，如 'P-1001'、'PROD-A001'
     - order_code（订单编码）→ 通常是 varchar，如 'ORD-2024-001'
     - invoice_code（发票编码）→ 通常是 varchar，如 'INV-001'
     - account_code（账户编码）→ 通常是 varchar
  ✅ **判断方法**：
     1. 查看白名单中的类型信息（varchar/char/text = 字符串，int/bigint = 数值）
     2. 如果类型是 varchar/char/text，**必须当作字符串处理**
     3. 如果注释中包含编码示例（如 'S001'、'C-001'），**一定是字符串类型**
  ❌ **错误示例**：
     ```sql
     -- ❌ 错误：supplier_code 可能是 'S001'（字符串），不能进行数值运算
     SELECT "supplier_name", SUM(CAST("supplier_code" AS INTEGER)) AS total_score
     ```
  ✅ **正确示例**：
     ```sql
     -- ✅ 正确：如果需要统计，按字符串处理或使用其他数值字段
     SELECT "supplier_name", SUM("amount") AS total_amount
     FROM suppliers
     GROUP BY "supplier_name"
     ```

- **日期时间类型字段**（date, timestamp, time 等）：
  ✅ 使用 =, <, >, BETWEEN 以及日期函数（如 CURRENT_DATE、DATE_ADD）

【第1阶段：时间维度动态处理】⭐⭐⭐⭐⭐（极其重要）
当用户提到时间相关的关键词时，必须使用数据库的动态时间函数，**绝对禁止硬编码具体日期**。

🚨🚨🚨 **铁律：禁止硬编码日期** 🚨🚨🚨
════════════════════════════════════════════════
⛔ **绝对禁止**以下行为：
1. ❌ 禁止使用固定年份：`WHERE "FIND_TIME" >= DATE '2024-07-01'`
2. ❌ 禁止使用固定日期：`WHERE "CREATE_TIME" < DATE '2024-10-01'`
3. ❌ 禁止假设当前年份是2024或其他固定值
4. ❌ 禁止在WHERE条件中使用任何具体的年、月、日数字

✅ **唯一正确做法**：
- 必须使用Trino的动态时间函数（CURRENT_DATE, CURRENT_TIMESTAMP, DATE_ADD等）
- 根据用户的时间关键词，计算相对于当前时间的范围
- 确保生成的SQL在任何时候执行都能得到正确的时间范围
════════════════════════════════════════════════

**1. 关键词识别与函数映射**⭐⭐⭐⭐⭐（最重要）

**当前时间关键词**：
- **"今年"、"本年度"、"当年"** → 使用 `YEAR("字段") = YEAR(CURRENT_DATE)`
  ```sql
  -- ✅ 正确：动态获取当前年份
  WHERE YEAR("FIND_TIME") = YEAR(CURRENT_DATE)
  
  -- ❌ 错误：硬编码年份
  WHERE "FIND_TIME" >= DATE '2024-01-01' AND "FIND_TIME" < DATE '2025-01-01'
  ```

- **"今天"、"当天"、"今日"** → 使用 `DATE("字段") = CURRENT_DATE`（适用于timestamp字段）
  ```sql
  -- ✅ 正确：timestamp字段提取日期部分后比较
  WHERE DATE("CREATE_TIME") = CURRENT_DATE
  WHERE DATE("update_time") = CURRENT_DATE
  
  -- ✅ 正确：date类型字段直接比较
  WHERE "sta_date" = CURRENT_DATE
  
  -- ❌ 错误：硬编码日期
  WHERE "CREATE_TIME" >= DATE '2024-11-24'
  
  -- ❌ 错误：类型不匹配（将date转换为VARCHAR比较）
  WHERE "sta_date" = CAST(CURRENT_DATE AS VARCHAR)
  
  -- ❌ 错误：对timestamp字段使用错误的转换方式
  WHERE CAST("update_time" AS VARCHAR) = CAST(CURRENT_DATE AS VARCHAR)
  ```

- **"当前"、"现在"、"目前"** → 根据上下文使用相应函数
  ```sql
  -- 如果指当前年份
  WHERE YEAR("字段") = YEAR(CURRENT_DATE)
  
  -- 如果指当前月份
  WHERE YEAR("字段") = YEAR(CURRENT_DATE) AND MONTH("字段") = MONTH(CURRENT_DATE)
  ```

**2. 季度处理**⭐⭐⭐⭐⭐（用户案例重点）
- **"第一季度"、"一季度"、"Q1"** → 使用 `QUARTER("字段") = 1`
- **"第二季度"、"二季度"、"Q2"** → 使用 `QUARTER("字段") = 2`
- **"第三季度"、"三季度"、"Q3"** → 使用 `QUARTER("字段") = 3`
- **"第四季度"、"四季度"、"Q4"** → 使用 `QUARTER("字段") = 4`

**示例（针对用户的具体需求）**：
"统计各区局今年第三季度的缺陷情况，按状态"
```sql
-- ✅ 正确的动态时间处理
SELECT t1."BUREAU_NAME", t1."STATE", COUNT(*) AS defect_count
FROM sp_pd_defect_03 AS t1
WHERE YEAR(t1."FIND_TIME") = YEAR(CURRENT_DATE)    -- 动态获取当前年份
  AND QUARTER(t1."FIND_TIME") = 3                  -- 第三季度
GROUP BY t1."BUREAU_NAME", t1."STATE"
ORDER BY t1."BUREAU_NAME", t1."STATE";

-- ❌ 错误：硬编码日期范围
WHERE t1."FIND_TIME" >= DATE '2024-07-01' AND t1."FIND_TIME" < DATE '2024-10-01'
```

**3. 相对时间处理**⭐⭐⭐（Trino专用语法）
- **"最近N天"** → 使用 `"字段" >= DATE_ADD('day', -N, CURRENT_DATE)`
- **"最近N周"** → 使用 `"字段" >= DATE_ADD('week', -N, CURRENT_DATE)`
- **"最近N个月"** → 使用 `"字段" >= DATE_ADD('month', -N, CURRENT_DATE)`
- **"最近N年"** → 使用 `"字段" >= DATE_ADD('year', -N, CURRENT_DATE)`

```sql
-- ✅ Trino正确语法：最近3年的数据
WHERE "CREATE_TIME" >= DATE_ADD('year', -3, CURRENT_DATE)

-- ✅ Trino正确语法：最近30天的数据
WHERE "order_date" >= DATE_ADD('day', -30, CURRENT_DATE)

-- ❌ MySQL语法在Trino中会报错
WHERE "order_date" >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)

-- ❌ PostgreSQL语法在Trino中会报错  
WHERE "order_date" >= CURRENT_DATE - INTERVAL '30 days'
```

**4. 月份处理**
- **"本月"、"当月"** → 使用 `YEAR("字段") = YEAR(CURRENT_DATE) AND MONTH("字段") = MONTH(CURRENT_DATE)`
- **"上月"、"上个月"** → 使用DATE_ADD函数计算
- **具体月份**："1月"、"一月" → `MONTH("字段") = 1`

🚨🚨🚨 特殊月份字段（YYYY-MM 字符串）处理规则（必须遵守）
若白名单字段中存在类似 stat_month / month 且其取值形如 2024-09（YYYY-MM），则该字段为 VARCHAR 月份字段，必须按字符串月份处理：

禁止：CAST("stat_month" AS INTEGER) 或将 YYYY-MM 强转为数值（会触发 INVALID_CAST_ARGUMENT）。

单月查询（如“2025年1月”）：使用

WHERE "stat_month" = '2025-01'（月份必须补零为两位）

月份范围查询（如“2025年1-11月”）：使用

WHERE "stat_month" BETWEEN '2025-01' AND '2025-11'

若用户给出年份+月份数字（如 1~11），必须转换为两位月份并拼成 YYYY-MM 再比较。

只有当字段本身是纯数字月份（如 1/01/12）时，才允许按数值比较；否则一律按 YYYY-MM 字符串规则处理。

**5. 日期字段类型判断与安全转换**⭐⭐⭐⭐⭐（防止INVALID_CAST_ARGUMENT错误）
在生成SQL前，必须判断字段的数据类型，选择合适的转换方式：

**字段类型判断规则**：
1. **timestamp类型字段**（包含日期和时间，如 `2025-12-08 07:52:59`）：
   - ✅ **提取日期部分**：`DATE("update_time") = CURRENT_DATE`
   - ✅ **安全转换**：`CAST("update_time" AS DATE) = CURRENT_DATE`
   - ❌ **绝对禁止**：`CAST("update_time" AS VARCHAR) = CAST(CURRENT_DATE AS VARCHAR)`（类型不匹配）
   - ❌ **绝对禁止**：`"update_time" = CAST(CURRENT_DATE AS VARCHAR)`（类型不匹配）

2. **date类型字段**（只包含日期，如 `2025-12-08`）：
   - ✅ **直接比较**：`"sta_date" = CURRENT_DATE`
   - ✅ **显式转换**：`CAST("sta_date" AS DATE) = CURRENT_DATE`
   - ❌ **绝对禁止**：`"sta_date" = CAST(CURRENT_DATE AS VARCHAR)`（类型不匹配）
   - ❌ **绝对禁止**：`CAST("sta_date" AS VARCHAR) = CAST(CURRENT_DATE AS VARCHAR)`（不必要的转换）

3. **varchar类型字段**（存储日期字符串）：
   - ✅ **安全转换**：`TRY_CAST("date_str" AS DATE) = CURRENT_DATE`
   - ✅ **解析转换**：`DATE_PARSE("date_str", '%Y-%m-%d') = CURRENT_DATE`
   - ❌ **绝对禁止**：直接 `CAST("date_str" AS DATE)`（如果格式不匹配会报错）

**常见错误示例与正确做法**：
```sql
-- ❌ 错误示例1：timestamp字段类型不匹配
WHERE "update_time" = CAST(CURRENT_DATE AS VARCHAR)
-- 错误原因：timestamp类型不能与VARCHAR类型比较
-- ✅ 正确做法：
WHERE DATE("update_time") = CURRENT_DATE

-- ❌ 错误示例2：date字段转换为VARCHAR比较
WHERE "sta_date" = CAST(CURRENT_DATE AS VARCHAR)
-- 错误原因：date类型应该直接与date类型比较，不需要转换为VARCHAR
-- ✅ 正确做法：
WHERE "sta_date" = CURRENT_DATE

-- ❌ 错误示例3：双重转换导致错误
WHERE DATE(CAST("update_time" AS VARCHAR)) = CURRENT_DATE
-- 错误原因：不必要的双重转换，可能导致格式错误
-- ✅ 正确做法：
WHERE DATE("update_time") = CURRENT_DATE
```

**6. 重要注意事项**⭐⭐⭐⭐⭐
1. **动态性原则**：生成的SQL必须在任何时间点执行都能返回正确的相对时间范围
2. **函数优先级**：优先使用Trino的内置时间函数而不是字符串比较
3. **性能考虑**：尽量使用能够利用索引的时间范围查询
4. **双引号语法**：Trino中字段名必须使用双引号包围
5. **类型匹配原则**：日期比较时，确保两边的类型一致（date与date比较，不要转换为VARCHAR）
6. **安全转换原则**：对于不确定类型的字段，优先使用TRY_CAST而不是CAST，避免转换失败

【第2阶段：比例与百分比计算】⭐⭐⭐⭐⭐（特别重要）
当用户询问比例、百分比、占比、完成率等统计时，需要使用除法运算和条件计数。

**核心规则**：

1. **识别比例计算需求**：
   - 关键词："消缺比例"、"及时消缺率"、"占比"、"百分比"、"完成率"、"通过率"
   - 本质：计算 **某个条件下的数量 / 总数量**
   - 示例："状态为4的缺陷数 / 总缺陷数"

2. **数值精度要求** ⭐⭐⭐（强制执行）：
   - ✅ **所有比例和百分比计算必须使用 ROUND 函数保留两位小数，并使用 CONCAT 拼接百分号**
   - ✅ 格式：`CONCAT(CAST(ROUND(计算表达式, 2) AS VARCHAR), '%')`
   - ✅ 示例：`CONCAT(CAST(ROUND(CAST(COUNT(CASE WHEN ...) AS DOUBLE) * 100.0 / COUNT(*), 2) AS VARCHAR), '%')`
   - ✅ 显示效果：`98.33%`（而不是 `98.33` 或 `99.96288`）
   - ❌ 禁止直接返回未格式化的小数，如 `99.96288`

3. **SQL实现方式**（3种推荐模式，注意Trino语法）：

   ✅ **方式1：单一比例统计**（适用于全局统计）
   ```sql
   SELECT 
       CONCAT(CAST(ROUND(CAST(COUNT(CASE WHEN "STATE" = 4 THEN 1 END) AS DOUBLE) / COUNT(*), 2) AS VARCHAR), '%') AS fix_ratio,
       CONCAT(CAST(ROUND(CAST(COUNT(CASE WHEN "STATE" = 4 THEN 1 END) AS DOUBLE) * 100.0 / COUNT(*), 2) AS VARCHAR), '%') AS fix_percentage
   FROM sp_pd_defect_03
   WHERE "PROVINCE_NAME" LIKE '%广东%'
   ```
   
   ✅ **方式2：按维度分组统计比例**（推荐，适用于分组统计）
   ```sql
   SELECT 
       "BUREAU_NAME",
       COUNT(*) AS total_count,
       COUNT(CASE WHEN "STATE" = 4 THEN 1 END) AS target_count,
       CONCAT(CAST(ROUND(CAST(COUNT(CASE WHEN "STATE" = 4 THEN 1 END) AS DOUBLE) / COUNT(*), 2) AS VARCHAR), '%') AS ratio,
       CONCAT(CAST(ROUND(CAST(COUNT(CASE WHEN "STATE" = 4 THEN 1 END) AS DOUBLE) * 100.0 / COUNT(*), 2) AS VARCHAR), '%') AS percentage
   FROM sp_pd_defect_03
   GROUP BY "BUREAU_NAME"
   ORDER BY ROUND(CAST(COUNT(CASE WHEN "STATE" = 4 THEN 1 END) AS DOUBLE) / COUNT(*), 2) DESC
   ```
   
   ✅ **方式3：使用窗口函数计算分组百分比**（适用于类别占比）
   ```sql
   SELECT 
       "DEFECT_TYPE",
       COUNT(*) AS cnt,
       CONCAT(CAST(ROUND(CAST(COUNT(*) AS DOUBLE) * 100.0 / SUM(COUNT(*)) OVER(), 2) AS VARCHAR), '%') AS pct
   FROM sp_pd_defect_03
   WHERE "PROVINCE_NAME" LIKE '%广东%'
   GROUP BY "DEFECT_TYPE"
   ORDER BY ROUND(CAST(COUNT(*) AS DOUBLE) * 100.0 / SUM(COUNT(*)) OVER(), 2) DESC
   ```

3. **字段白名单要求**（严格遵守）：
   - ✅ 所有引用的字段（如 "STATE", "BUREAU_NAME"）**必须在白名单中**，使用双引号包裹
   - ✅ 计算结果必须使用 AS 定义别名（如 ratio, percentage, fix_rate）
   - ❌ 不要使用不存在的字段或虚构的比例字段
   - ✅ 如果白名单中已存在比例字段，优先使用该字段

4. **典型应用场景**（Trino语法）：

   **场景0：商品销售查询（含时间条件）**⭐⭐⭐
   用户问："价格低于150，且近30天销量大于100的商品有哪些？"
   ```sql
   -- ✅ Trino正确语法
   SELECT 
       t1."product_id",
       t1."name",
       t1."category", 
       t1."price"
   FROM "product_catalog" AS t1
   JOIN "sales_orders" AS t2 ON t1."product_id" = t2."product_id"
   WHERE t1."price" < 150
     AND t2."order_date" >= DATE_ADD('day', -30, CURRENT_DATE)
   GROUP BY t1."product_id", t1."name", t1."category", t1."price"
   HAVING SUM(t2."qty") > 100
   ```

   **场景1：各地市局的消缺比例统计**
   用户问："各地市局的消缺比例统计（消缺比例=已安排消缺数量/总数）"

   **场景2：及时消缺率统计**

   ```sql
   SELECT
   ```

   **场景4：跨catalog库存和销量关联查询**⭐⭐⭐

   ```sql
   -- ✅ Trino跨catalog完整JOIN语法示例
   -- ⚠️⚠️⚠️ 关键警告：必须使用白名单中实际存在的列！

   FROM "mysql8"."webtest1"."device_m8" AS d

   GROUP BY d."device_code", d."device_name", d."location"
   ```

5. **重要技术细节**：
   - **浮点数除法**：Trino 需要使用 `CAST(... AS DOUBLE)` 将整数转为浮点数，避免整数除法截断
   - **精度控制**：使用 `ROUND(表达式, 2)` 保留两位小数
   - **百分号拼接**：使用 `CONCAT(CAST(ROUND(..., 2) AS VARCHAR), '%')` 在结果后添加百分号
   - **排序注意事项**：当字段使用CONCAT添加百分号后变为字符串类型，ORDER BY时需使用原始数值表达式
     ```sql
     -- 错误：ORDER BY percentage（字符串排序，"9%" > "80%"）
     -- 正确：ORDER BY ROUND(...原始计算表达式..., 2) DESC
     ```
   - **除数为0处理**：如果可能出现除数为0，使用 NULLIF 保护
     ```sql
     CONCAT(CAST(ROUND(CAST(COUNT(CASE WHEN 条件 THEN 1 END) AS DOUBLE) * 100.0 / NULLIF(COUNT(*), 0), 2) AS VARCHAR), '%') AS percentage
     ```
   - **百分比 vs 小数**：
     * 乘以 100 → 百分比形式（如 75.5 表示75.5%）
     * 不乘 → 小数形式（如 0.755）
   - **排序逻辑**：通常按比例降序（ORDER BY ratio DESC）查看排名前列
   - **日期计算**：Trino 使用 DATE_DIFF('unit', start, end) 函数计算日期差

6. **错误避免**⭐：
   - ❌ 错误：假设存在 "fix_ratio" 字段（如果白名单中没有）
   - ✅ 正确：使用计算表达式 `CAST(COUNT(CASE WHEN ...) AS DOUBLE) / COUNT(*) AS fix_ratio`
   - ❌ 错误：整数除法 `COUNT(...) / COUNT(*)` → 结果只能是0或1
   - ✅ 正确：浮点除法 `CAST(COUNT(...) AS DOUBLE) / COUNT(*)` → 结果是0到1之间的小数
   - ❌ 错误：忘记使用 CAST AS DOUBLE 进行类型转换
   - ✅ 正确：Trino 需要显式类型转换才能得到浮点除法结果
   - ❌ 错误：忘记使用双引号包裹字段名
   - ✅ 正确：Trino 字段名必须用双引号 "FIELD_NAME"

【Trino常见错误预防】⭐⭐⭐⭐⭐（极其重要）
以下是Trino中最容易出错的语法，必须严格避免：

**1. 时间函数错误预防**：
❌ **绝对禁止**：
```sql
-- MySQL语法
DATE_SUB(CURDATE(), INTERVAL 30 DAY)
DATE_ADD(CURDATE(), INTERVAL -30 DAY)
NOW() - INTERVAL 30 DAY

-- PostgreSQL语法  
CURRENT_DATE - INTERVAL '30 days'
CURRENT_TIMESTAMP - INTERVAL '1 month'

-- SQL Server语法
DATEADD(DAY, -30, GETDATE())
DATEDIFF(DAY, start_date, end_date)
```

✅ **Trino正确语法**：
```sql
-- 日期计算
DATE_ADD('day', -30, CURRENT_DATE)
DATE_ADD('month', -1, CURRENT_DATE)

-- 日期差计算
DATE_DIFF('day', "start_date", "end_date")

-- 当前时间
CURRENT_DATE, CURRENT_TIMESTAMP
```

**2. 字符串函数错误预防**：
❌ **错误**：`CONCAT_WS('-', field1, field2)` （MySQL语法）
✅ **正确**：`"field1" || '-' || "field2"`

❌ **错误**：`SUBSTRING("field", 1, 10)` （某些数据库语法）  
✅ **正确**：`SUBSTR("field", 1, 10)`

**3. 数据类型转换错误预防**：
❌ **错误**：直接除法 `COUNT(condition) / COUNT(*)`（结果是整数0或1）
✅ **正确**：`CAST(COUNT(condition) AS DOUBLE) / COUNT(*)`

❌ **错误**：`CONVERT(VARCHAR, field)` （SQL Server语法）
✅ **正确**：`CAST("field" AS VARCHAR)`

- “若字段值形如 YYYY-MM，禁止 CAST 为 INTEGER，范围过滤用字符串 BETWEEN。”

**4. 聚合函数错误预防**：
❌ **错误**：`GROUP_CONCAT("field")` （MySQL语法）
✅ **正确**：`ARRAY_AGG("field")` 或 `LISTAGG("field", ',')`

❌ **错误**：`STRING_AGG("field", ',')` （PostgreSQL语法）
✅ **正确**：`ARRAY_JOIN(ARRAY_AGG("field"), ',')`

**5. 条件聚合错误预防**：
❌ **错误**：
```sql
SUM(IF(condition, 1, 0))  -- MySQL语法
SUM(IIF(condition, 1, 0)) -- SQL Server语法
```

✅ **正确**：
```sql
SUM(CASE WHEN condition THEN 1 ELSE 0 END)
COUNT(CASE WHEN condition THEN 1 END)
```

**6. NULL处理错误预防**：
❌ **错误**：`ISNULL(field, default)` （SQL Server语法）
❌ **错误**：`IFNULL(field, default)` （MySQL语法）
✅ **正确**：`COALESCE("field", default)` 或 `CASE WHEN "field" IS NULL THEN default ELSE "field" END`

**7. TOP/LIMIT语法错误预防**：
❌ **错误**：`SELECT TOP 10 ...` （SQL Server语法）
❌ **错误**：`LIMIT 10` 放在WHERE之前
✅ **正确**：`LIMIT 10` 放在查询最后，或使用 `ROW_NUMBER() OVER() <= 10`

**8. 引号使用错误预防**：
❌ **绝对禁止**：
```sql
SELECT `field` FROM table          -- MySQL反引号
SELECT [field] FROM [table]        -- SQL Server方括号  
SELECT field FROM table            -- 无引号
```

✅ **唯一正确**：
```sql
SELECT "field" FROM "table"        -- Trino双引号
```

【枚举值映射规则】⭐⭐⭐（特别重要）
当字段注释包含状态枚举说明时，必须根据注释中的数字映射关系来使用正确的枚举值：

**状态字段处理原则**：
1. **仔细阅读字段注释**：如果字段注释包含状态枚举（如"1：待上报；2：待审批；3：待安排消缺；4：已安排消缺；5：待验收；6：已归档；7：已删除"），必须使用注释中的数字值。

2. **常见状态映射示例**：
   - "待上报" → 1
   - "待审批" → 2  
   - "待安排消缺" → 3
   - "已安排消缺" → 4
   - "待验收" → 5
   - **"已归档" → 6** ⭐⭐⭐
   - "已删除" → 7
   - "缺陷记录审核" → 8
   - "计划消缺" → 9
   - "备品备件确认" → 10

3. **处理逻辑**：
   - 用户说"状态为已归档"时，必须使用 WHERE "STATE" = 6
   - 用户说"待验收的缺陷"时，必须使用 WHERE "STATE" = 5
   - **禁止猜测或使用错误的枚举值**

4. **扩展规则**：
   - 如果遇到其他枚举字段（如专业类型、等级等），同样根据字段注释中的数字映射关系处理
   - 如果字段注释不明确，优先使用数字值进行精确匹配，避免使用文本模糊匹配

5. **特殊字段：等级/严重程度字段** ⭐⭐⭐（特别重要）：
   - **缺陷等级字段**（如 "DEFECT_LEVEL"）通常是**反向枚举**：数字越小等级越高
   - **常见等级映射**（数字越小越严重）：
     * 1：紧急/严重（最高优先级）
     * 2：重大/高
     * 3：一般/中等
     * 4：其他/轻微（最低优先级）
   - **查询逻辑**：
     * 用户问"最严重的缺陷" → 使用 MIN("DEFECT_LEVEL") 取最小值
     * 用户问"最轻微的缺陷" → 使用 MAX("DEFECT_LEVEL") 取最大值

    - ❌ 禁止：CONVERT(VARCHAR, field)

17) **NULL处理语法检查**：
    - ✅ 正确：COALESCE("field", 'default')
    - ❌ 错误：ISNULL("field", 'default'), IFNULL("field", 'default')

18) **字符串连接语法检查**：
    - ✅ 正确：`"field1" || '-' || "field2"`

【Trino性能优化与最佳实践】⭐⭐⭐
为确保查询性能，请遵循以下最佳实践：

**1. 过滤条件优化**：
- ✅ **尽早过滤**：将过滤条件尽量下推到WHERE子句，而不是HAVING
- ✅ **分区字段优先**：优先使用分区字段（如日期字段）进行过滤
- ✅ **示例**：
  ```sql
  -- ✅ 好：过滤条件在WHERE中
  SELECT "region", COUNT(*) FROM "catalog"."schema"."table"
  WHERE "create_date" >= DATE_ADD('day', -30, CURRENT_DATE)
  GROUP BY "region"
  
  -- ❌ 差：过滤在HAVING中（性能差）
  SELECT "region", COUNT(*) FROM "catalog"."schema"."table"
  GROUP BY "region" 
  HAVING COUNT(*) > 1000
  ```

**2. JOIN优化**：
- ✅ **小表在右**：将较小的表放在JOIN的右侧
- ✅ **精确JOIN条件**：使用精确的等值连接条件
- ✅ **避免笛卡尔积**：确保所有JOIN都有明确的ON条件

**3. 跨catalog查询优化**：
- ✅ **减少数据传输**：在各个catalog内尽量完成过滤和聚合
- ✅ **合理的JOIN策略**：大表之间的JOIN尽量在同一catalog内完成
- ✅ **示例**：
  ```sql
  -- ✅ 好：先在各catalog内过滤，再JOIN
  WITH mysql_products AS (
    SELECT "product_id", "name", "price" 
    FROM "mysql_catalog"."shop"."products" 
    WHERE "price" > 100
  ),
  pg_orders AS (
    SELECT "product_id", SUM("quantity") as total_qty
    FROM "postgresql_catalog"."sales"."orders"
    WHERE "order_date" >= DATE_ADD('day', -30, CURRENT_DATE)
    GROUP BY "product_id"
    HAVING SUM("quantity") > 10
  )
  SELECT mp."name", pg.total_qty
  FROM mysql_products mp
  JOIN pg_orders pg ON mp."product_id" = pg."product_id"
  ```

**4. 查询复杂度管理**：
- ✅ **分解复杂查询**：将复杂查询分解为多个步骤
- ✅ **使用CTE**：通过WITH子句提高可读性和性能
- ✅ **避免深层嵌套**：减少子查询嵌套层数
