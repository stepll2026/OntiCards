**前置数据库表结构情况摸排**

- **问题**：导入的数据源中，所有库表的字段均缺乏注释。
- **影响**：系统基于表名、字段名、类型等推断业务语义存在主观性，可能导致检索结果与实际不符。
- **建议**：通过工作空间【增强】Tab 栏上传数据字典文件批量补充字段注释。

**数据字典文件格式（参考）**：


| 字段名 | 字段类型    | 字段注释   |
| --- | ------- | ------ |
| 字段1 | VARCHAR | 字段1的注释 |
| 字段2 | INTEGER | 字段2的注释 |

## 1. 是否存在独立的确定性指标/语义层

**现状说明**：平台具备"轻量语义层"，但不是完整的指标平台。

**已具备的语义能力**

- **业务术语库（核心语义层）**：每个术语绑定标准定义、同义词，关联到数据库字段或字段取值条件，实现业务口径标准化，查询时按定义精准解析，不依赖模型自由发挥。
- **数据卡片（字段语义层）**：为每张表、每个字段生成"业务说明书"（字段含义、典型值、取值范围、查询场景），解决"这是什么字段、怎么用"的问题。

**未提供的能力**

- 维度和度量建模、指标血缘、指标版本管理

---

## 2. Agent 的计划、工具、记忆、审批、重试和可观测能力是否在系统中验证

**定位**：OntiCards 是"取数能力底座"，不是 Agent 平台，上述能力不在系统范围内。

**OntiCards 提供的能力链路（取数层）**

```
数据源 → 元数据/数据卡片 → 关系盘点 → 术语库 → NL2SQL → SQL执行
      → 查询结果 → 历史/监控/成本
      → [可选] 质检（基础检测 + 一致性校验）→ 生成质检报告
```

**不在 OntiCards 范围（由上层 Agent 平台负责）**

- 任务分解与计划生成、多轮记忆 / 长期记忆、人工审批节点、多证据多步骤报告合成、Agent 工具调度 / 重试 / 可观测性

## 3. 是否支持字段分级分类、RBAC/ABAC、行列级权限和动态脱敏

**现状说明**：当前版本不支持细粒度权限体系。

**当前已支持的访问控制**


| 维度       | 状态  | 实现方式                  |
| -------- | --- | --------------------- |
| 系统级用户隔离  | 已支持 | 每个用户只能访问自己添加的数据源      |
| 数据源级隔离   | 已支持 | 用户级 + 数据库账号权限双重隔离     |
| 角色控制     | 基础  | 仅"普通用户 / 管理员"两类角色     |
| 字段白名单    | 已支持 | 底层获取允许查询的字段列表         |
| SQL 执行限制 | 已支持 | 仅允许 SELECT，配合 SQL 白名单 |


**当前未支持（规划中）**

- 敏感字段脱敏、RBAC / ABAC、行级权限、列级权限（基于策略）、动态脱敏

**隔离机制**：OntiCards 系统用户体系 + 数据库账号原生权限两层协同。用户之间通过系统账号隔离数据源可见性，落到数据库后由连接该数据源的数据库账号实际权限决定可访问范围。

**后续规划**：细粒度权限体系（RBAC + 字段分级 + 行列级控制 + 动态脱敏）将在后续升级版本中提供。当前阶段建议通过数据源端专用只读账号 + 库表/视图设计实现最小权限约束。

## 4. SQL 重试修正后，历史记录中记录的 SQL 未更新

- **问题**：SQL 执行失败后系统自动修正并重试成功，但历史记录中记录的仍是首次失败 SQL，与实际执行的 SQL 不一致。
- **原因**：历史记录写入时机早于重试修正动作。
- **修复结果**：已修复。聚合检索过程中，SQL 重试成功后，历史查询中记录的是重试后的正确 SQL，接口与页面展示的 `target_sql` 与数据库实际执行的 SQL 保持一致。

---

## 5. 质检 SQL 未使用 Schema 前缀

- **问题**：质检规则生成 SQL 时未使用目标数据库的 Schema 前缀，导致执行时报"表不存在"错误。
- **原因**：质检 SQL 生成依赖了连接账号的默认 Schema，而非关联数据源配置的 Schema。
- **修复结果**：已修复。数据质检功能模块在添加规则环节生成质检 SQL 时，针对有 Schema 概念的数据库（PostgreSQL、SQL Server、KingBase 等）正确使用 `schema.table` 格式，不再依赖连接账号默认 Schema。

---

## 6. 数据卡片中模型推断内容与真实元数据不符

- **问题**：数据卡片中部分枚举值和标签（如客户状态的"VIP / 活跃 / 流失"、术语表中的"GMV / DAU / ROI"等）并非来自数据库事实，属于模型预设举例。
- **原因**：数据卡片生成提示词未明确约束模型必须基于真实元数据生成内容。
- **修复结果**：已优化数据卡片生成提示词，严格约束模型行为：
  - **枚举值**：仅使用字段注释中已有的内容，禁止捏造
  - **质量检查**：生成时校验枚举值完整性
