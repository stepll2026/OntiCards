# 日志中心

侧边栏新增“日志中心”，页面路由为 `/{lng}/log-center`，延续项目已有语言路由规则。

## 查询日志

登录用户可以查看自己的查询记录，按关键词（问题、SQL、错误原因）、状态和日期筛选。
列表和详情复用 `query_history` API，旧客户端传自己的 `user_id` 仍兼容；身份以服务端登录用户为准，传其他用户 ID 返回 403。读取、统计和删除均受同样的所有权校验保护。

聚合查询完成后保存每个查询簇的 SQL 生成、校验、执行及模型纠错过程。记录阶段、尝试序号、状态、SQL 快照、错误码、消息和耗时；最多两次纠错不变。失败查询也保存 SQL、用量和执行过程。模型错误区分 HTTP 错误、超时、连接失败和缺失/无效响应。

复用 `query_logs.cluster_sqls` 与 `full_response_result` 的 JSONB 字段，无新增表或列，无需数据库迁移。老记录仍可查看已有内容，缺少纠错记录时展示“未记录纠错详情”；旧记录的纠错次数为未知（unknown/未记录），不能解释为 0 次，不回填或伪造历史。

新增诊断每簇最多 24 条，每个文本字段最多 12,000 字符；诊断中的凭据脱敏，连接配置不进入诊断。原有查询回放的完整 SQL、问题、术语及业务结果不因新增日志而截断。原查询内容仍按原有授权查询历史语义保存，仅本人可访问。

## 系统日志

只有 `admin` 用户可以调用 `GET /console/api/log_center/system`。页面支持级别、关键词、日期、分页、手动刷新及每 10 秒刷新，可查看和复制单条脱敏诊断。

记录请求的路由模板、方法、状态码、耗时和服务端生成的请求 ID，以及 Python WARNING/ERROR 事件。不会采集请求参数、请求头、请求体、响应体或旧 `flask.log` 原文。后台任务没有请求上下文时，请求字段为空。

系统日志使用现有 API 的 `logs` 目录中的 `system-events.jsonl`，单文件最多 10 MiB、最多 5 个备份，使用跨进程文件锁协调写入和轮转。每次最多检索最近 8 MiB / 20,000 条；筛选和分页仅在这个读取窗口内执行，返回的 `total` 是窗口内匹配数，不是全部历史记录数。`truncated=true` 时页面显示范围受限提示，指定早期日期也不能读取窗口之外或已轮转清理的内容。日期筛选按 UTC+8 自然日解释，时间戳保存为 UTC。

查询日志在查询结束后写入，系统请求记录在响应完成后写入；不是执行中的逐字流式日志。系统日志采用 best effort（尽力记录）：日志写入失败或文件锁竞争超时不会中断业务请求，因此可能缺少相应记录，不保证完整审计或可靠消息投递。系统日志读取失败返回 503；未登录返回 401，非管理员返回 403。

## 部署与验证

需要重新构建并更新 API 和 Web 镜像。保持现有 API `logs` 目录挂载，才能在重建容器后保留系统日志；未挂载时仅保存在该容器文件系统中。本次不自动变更部署文件、数据库或客户服务器。

离线测试仅安装下列依赖子集。运行依赖版本与 `requirements.txt` 一致，`pytest` 为测试工具：

```bash
python -m pip install pytest==8.4.2 SQLAlchemy==2.0.36 sqlglot==30.18.0 \
  Flask==2.3.3 Flask-Login==0.6.3 Flask-RESTful==0.3.10 \
  Flask-SQLAlchemy==3.1.1 Werkzeug==3.0.6 requests==2.32.3
python -m pytest -q OntiCards_Api/tests
```

真实 PostgreSQL 对照的运行方式见 `tests/README.md`。日志专项用例使用临时 Flask 应用、SQLite 或临时日志目录，不读取业务数据库。

前端需分别执行依赖安装、TypeScript、ESLint 和生产构建；现有 Next.js 配置会在构建时跳过类型与 lint 检查，构建成功不能代替这两项验证。
