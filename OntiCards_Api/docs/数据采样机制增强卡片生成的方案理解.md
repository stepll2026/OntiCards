# 数据采样机制增强卡片生成的方案理解

## 完整流程概览

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         数据卡片生成完整流程                              │
└─────────────────────────────────────────────────────────────────────────┘

阶段1：采样（先采样，后脱敏）
├── 对表中所有字段执行采样
├── 采样结果暂存（供后续 AI 分析用）
└── 采样 SQL 需要方言适配 + Schema 正确

       ↓

阶段2：AI 脱敏分析（调用大模型）
├── 输入：字段信息 + 采样数据
├── 输出：{ "sensitive_fields": [...], "reasons": {...} }
├── 判断依据：
│   ├── 字段名语义（phone、id_card、password...）
│   ├── 采样数据模式（手机号格式、身份证格式...）
│   └── 行业通用规则
└── 不输出：敏感字段的数据示例

       ↓

阶段3：AI 业务语义分析
├── 输入：采样数据（排除敏感字段）
├── 输出：
│   ├── 枚举类字段（distinct < 50）
│   ├── 数值类字段 → 统计摘要
│   ├── 日期类字段 → 日期范围
│   └── 文本类字段 → 简短示例
└── 结果：非敏感字段都有数据示例

       ↓

阶段4：大模型生成数据卡片
├── 输入上下文：
│   ├── 表结构 + 注释
│   ├── 枚举值采样（非敏感）
│   ├── 数值统计摘要（非敏感）
│   └── 文本示例（非敏感）
└── 输出：
    ├── Abstract、Domain、KeyConcepts、Tags
    └── 字段描述（基于采样数据生成）

       ↓

阶段5：字段注释 AI 填充（配套能力）
├── 场景：字段注释为空
├── 输入：字段信息 + 采样数据（已脱敏）
├── 处理：
│   ├── 敏感字段：只填充「字段类型」说明，不输出数据示例
│   └── 非敏感字段：填充注释 + 可选的简短数据示例
└── 结果：所有字段都有注释
```

---

## 关键决策点


| 问题              | 方案             | 理由                |
| --------------- | -------------- | ----------------- |
| 采样前脱敏 vs 采样后脱敏？ | **采样后脱敏**      | 大模型需要看到数据才能判断是否敏感 |
| 敏感字段如何处理？       | **过滤，不输出数据示例** | 字段名/类型保留，但数据不暴露   |
| 字段注释填充是否脱敏？     | **是**          | 敏感字段注释仅填充「字段类型」说明 |
| 采样结果是否缓存？       | **是**          | 避免重复查询            |

## 完整流程示例：用户表 t_user

### 阶段1：表结构信息

```
表名: t_user
Schema: public

| 字段名      | 类型         | 注释     | 是否为空 |
|------------|-------------|---------|---------|
| id         | BIGINT      | 主键ID   | NO      |
| username   | VARCHAR(50) | 用户名    | NO      |
| password   | VARCHAR(255)| (空)     | NO      |
| phone      | VARCHAR(20) | 手机号    | YES     |
| id_card    | VARCHAR(18) | 身份证号  | YES     |
| email      | VARCHAR(100)| 邮箱地址  | YES     |
| balance    | DECIMAL(12,2)| 账户余额 | YES     |
| created_at | TIMESTAMP   | 创建时间  | NO      |
| status     | INTEGER     | 状态     | YES     |
| city       | VARCHAR(50) | 城市     | YES     |
```

## 接口兼容性保证

- **数据卡片接口**：输入输出结构保持不变
- **采样流程**：在后台静默执行
- **字段注释填充**：仅在注释缺失时触发，返回格式不变
- **用户体验**：仅感受到数据卡片质量提升（注释更准确、非敏感字段有数据示例）
