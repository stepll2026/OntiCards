## v4.1.0 版本更新日志（2026-07-29）

### ✨ 新功能

#### 国产数据库支持：达梦（DMBase）

OntiCards 现已支持**武汉达梦（DMDB）国产数据库**，后续将拓展对更多国产数据库的兼容。

**支持的特性：**

- 数据源连接与测试
- 智能数据卡片生成
- 自然语言转 SQL 查询（聚合检索）
- 系统自适应的空值检测函数
- 数据质检规则执行与报告生成

**技术说明：**

- 达梦数据库是国产大型关系型数据库，具有完全自主知识产权
- 系统自动适配达梦 SQL 方言，确保查询语法正确
- 达梦兼容 Oracle 语法，部分场景下可参考 Oracle 方言处理

---

#### 国产数据库支持：OceanBase（MySQL 租户模式）

OntiCards 现已支持**蚂蚁集团 OceanBase 国产分布式数据库的 MySQL 租户模式**。

> **💡 TIP**：OceanBase 原生提供了 MySQL 与 Oracle 双兼容模式，当前版本已支持 **MySQL 租户模式**；**Oracle 租户模式将在后续版本中实现支持**，敬请期待。

**技术说明：**

- OceanBase MySQL 租户在协议层兼容 MySQL
- 系统底层使用标准的 SQLAlchemy MySQL 方言，并针对 OceanBase 输出中独有的索引 DDL 扩展进行了兼容，避免反射警告
- 表/列/主键/外键/索引的识别及查询与 MySQL 行为完全一致
- 数据库结构概念与维度和 MySQL 保持一致（无 schema ）

---

#### 国产数据库支持：电科金仓（KingBase）

OntiCards 现已支持**电科金仓（KingBase，原名：人大金仓）**国产数据库，后续将拓展对更多国产数据库的兼容。

**支持的特性：**

- 数据源连接与测试
- 智能数据卡片生成
- 自然语言转 SQL 查询（聚合检索）
- 系统自适应的空值检测函数
- 数据质检规则执行与报告生成

**技术说明：**

- KingBase 基于 PostgreSQL 内核，语法高度兼容 PostgreSQL
- 系统自动适配 SQL 方言，确保查询语法正确

---

- **数据治理模块 - 数据质检**：提供完整的数据质量检查能力，帮助企业建立数据质量保障体系
  - **规则库管理**：按业务领域或数据类型创建规则库，每个规则库关联一个数据源，支持集中管理和复用
  - **质检规则管理**：支持三种创建方式，满足不同用户需求
    - 模板模式：从预设的规则模板中选择，系统已为常见场景预置规则，开箱即用
    - AI自然语言模式：用日常语言描述规则，系统自动转换为质检规则，如"检查邮箱格式是否正确"
    - 手动模式：直接配置规则各项参数，适合有经验的用户精细控制
  - **多类型规则支持**：支持非空检查、唯一性检查、格式校验、范围检查、枚举值检查、正则匹配、跨表比对、自定义SQL等多种规则类型
  - **规则执行**：批量执行质检规则，自动收集检测结果，支持基础空值检测和表关系发现等可选扩展模块
  - **质量评分体系**：基于通过率计算质量评分，提供优秀(≥95)、良好(≥85)、一般(≥70)、较差(≥60)、差(<60)五个等级
  - **质量概览**：提供全局数据质量监控视图，展示质量评分、问题趋势、问题分布和达标率等核心指标
  - **质检报告生成**：生成详细的质量报告，当前支持Markdown导出格式(后续拓展为Word/PDF/Excel)，包含AI智能总结功能

### ⚙️ 功能优化 / 调整

- **交互体验优化**：优化多处界面交互细节，提升操作流畅度
- **多数据库语法适配**：系统自动适配不同数据库的语法规则，支持MySQL、PostgreSQL、SQL Server、Oracle、SQLite、Trino、达梦（DMBase）、电科金仓（KingBase）、OceanBase 等多种数据库
- **深色模式适配优化**：各模块页面组件全面适配深色模式，提供更舒适的低光环境使用体验
- **空数据友好提示**：优化空数据时的组件呈现效果，当数据为空时显示"暂无数据"等友好提示
- **界面显示一致性**：优化各页面及Tab栏等模块的样式显示，确保视觉风格统一
- **数据质检模块统一化**：
  - 基础空值检测的执行明细结果并入基于规则库质检体系
  - 两种质检模式的执行明细统一存储，形成完整的质量检测留痕
  - 便于后续数据治理阶段的实施，提供统一的质检结果查询入口
  - 质检报告统一呈现两种模式的检测结果，呈现清晰、一目了然

---

### 📘 注意事项

- 数据治理分为两个阶段：**第一阶段为数据质检**（当前功能），**第二阶段为实际治理**（规划中）
- 规则库建议按业务线或数据类型创建，便于管理和复用
- 质量报告当前支持Markdown导出格式，后续拓展更多支持，满足合规审计和团队沟通需求
- 质检执行可能消耗一定数据库资源，建议在业务低峰期执行大规模质检
- 使用质检功能时，建议确保业务系统数据库（数据源或数据空间中的相关数据库表）没有实时数据更新变动，否则可能影响质检结果的准确性
- 质检过程中针对的数据范围是静态数据场景，请合理安排执行时间
